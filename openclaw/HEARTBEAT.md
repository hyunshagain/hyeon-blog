# HEARTBEAT — 블로그 운영 작업

OpenClaw의 heartbeat 스케줄. 자연어로 쓴다.

전제:

- `openclaw/RULES.md`의 금지 항목을 항상 지킨다. **머지는 절대 하지 않는다.**
- **OpenClaw는 작업용 맥북과 다른 컴퓨터에서 돌고, 연락 수단은 텔레그램뿐이다.**
  내 로컬 프로젝트 폴더를 볼 수 없다. 무엇을 했는지는 **나에게 물어봐야 한다.**
- 접근 가능한 것은 이 저장소, GitHub API, 그리고 공개된 사이트뿐이다.

---

## 매주 월요일 오전 9시 — 글감 물어보기

텔레그램으로 먼저 물어볼 것:

> 이번 주에 뭐 했어? 남길 만한 거 있으면 한 줄로 알려줘.
> 프로젝트든 실험이든 삽질이든 상관없어.

답이 오면 후보를 **3개 이내**로 정리해서 다시 보낼 것. 각 후보마다:

- 한 줄 제목안
- 이 글에 쓸 수 있는 **산출물**이 뭔지 — 차트·스크린샷·데이터셋·측정값·코드 중 무엇인지 구체적으로
- 왜 지금 남길 만한지 한 문장

산출물을 특정할 수 없는 주제는 후보에서 빼고, **왜 뺐는지 알려줄 것.** 그런 주제는 게이트를 통과하지 못한다.

답이 없으면 수요일 오전에 한 번만 더 묻는다. 그래도 없으면 그 주는 넘어간다. 재촉하지 않는다.

## 내가 주제를 고르면 — 초안 골격 준비

1. `draft/<slug>` 브랜치를 만든다. slug는 `YYYY-MM-DD-영문-요약` 형식.
2. `content/_research/<slug>.md` 에 리서치 노트를 쓴다. 출처 URL을 반드시 함께 적는다.
   이 파일은 발행되지 않는다.
3. `src/content/posts/ko/<slug>.md` 에 **골격만** 만든다:
   - frontmatter (title, description, pubDate, tags, `draft: true`, evidence 후보, sources)
   - H2 제목 3~5개 — **이전 글들과 다른 뼈대로.** 같은 틀을 반복하면 게이트 4번에 걸린다
   - 빈 `<!-- analysis:start -->` / `<!-- analysis:end -->` 블록
   - 문단은 쓰지 않는다. 비워둔다.
4. draft PR을 연다. PR 본문에 리서치 노트 요약과 내가 확인해야 할 사실을 적는다.
5. 텔레그램으로 PR 링크를 보낸다.

## 내가 초안을 채워서 push하면 — 비평

PR에 **코멘트로만** 남긴다. 본문 파일은 수정하지 않는다.

- 논리가 건너뛴 곳
- 근거 없이 단정한 문장
- H2 골격이 이전 글들과 비슷해 보이는지
- 사실 확인이 필요한 숫자나 인용
- 분석 블록에 조사 내용이 섞여 있는지 — 그 자리는 판단만 들어가야 한다

칭찬은 쓰지 않는다. 고칠 곳만 쓴다.

## CI가 실패하면 — 즉시 알림

품질 게이트가 실패하면 실패한 검사 이름과 사유를 텔레그램으로 요약해 보낼 것.
**게이트 스크립트나 cliches.json을 고쳐서 통과시키려 하지 말 것.** 글을 고쳐야 한다.

## 매주 금요일 오후 6시 — 상태 리포트

- GitHub Actions 최근 실행 결과 (성공 / 실패)
- https://hyeon-blog.vercel.app 접속 확인
- 사이트에 걸린 외부 링크 유효성 검사 — 깨진 링크 목록
- 지난 7일간 발행 편수 — 2편을 넘었으면 그 사실을 명시할 것
- 열려 있는 PR 중 7일 이상 방치된 것

## 한국어 원본이 발행되고 3일 뒤 — 번역 제안

해당 글의 영어 번역 초안을 `draft/<slug>-en` 브랜치에 만들고 PR을 연다.

- `src/content/posts/en/<slug>.md`, `draft: true`
- **원문의 문장을 옮기는 것이지 새로 쓰는 게 아니다.** 내용을 추가하거나 빼지 않는다.
- 분석 블록도 그대로 옮긴다.
- PR 본문에 번역이 애매했던 문장을 목록으로 적는다.
